# Self-audit

Findings from the review of the Signing Guard before its public release, with what was done about each. Severity is what a successful exploit would cost, not how likely it is. Each fix has a regression test next to the code it covers.

The review assumed five attackers: someone holding the bot's Fireblocks API credential (who can submit any transaction and have the co-signer forward it honestly signed), someone on the network path between co-signer and guard, someone who can reach the guard's port without a co-signer JWT, a broken or compromised price source, and an operator making a config mistake. It covered every source file, the Dockerfile and compose example, and the lockfile. Two passes: a line-by-line review, then an independent adversarial review that ran probes against the compiled guard.

Neither pass found a way for the credential holder alone to get a signature outside the policy from a correctly configured guard. The serious findings are about what a bad price source or a config mistake can do.

| id | severity | finding | status |
|---|---|---|---|
| SG-01 | medium | Nothing bounded the reference price itself. A source quoting the inverse pair, a power-of-ten error or a compromised source reporting 1000x became the reference, and an order selling inventory for almost nothing sat inside the band. | Fixed: `price.min_price` / `price.max_price` (required); a mid outside them is a price error and orders reject as `price_stale`. |
| SG-02 | medium | A wrong token `decimals` or swapped `base_token` / `quote_token` makes the guard approve wrong amounts, and the acceptance suite passes because it builds its cases from the same config. | Mitigated: SG-01's range catches a swapped orientation; `check-config` and the startup log print each token's decimals, each cap in atoms and the price orientation. Decimals stay the operator's to verify against the token contract; the guard has no chain access by design. |
| SG-03 | low | Anyone reaching the port could hold 1 MiB per connection before the JWT check, with no connection cap, and the 15 s request timeout fired at about 30 s. | Fixed: 256 KiB body cap, 256 connections, timeouts checked every second, 10 s TLS handshake timeout. Docs say to expose the port to the co-signer only. |
| SG-04 | low | The ticker fetch followed redirects (so an https URL could end on plain http) and read the whole body. | Fixed: `redirect: 'error'`, 64 KiB read cap, `price.url` checked with the URL parser. |
| SG-05 | low | A `__proto__` entry in typed-data `types` replaced the parsed map's prototype instead of adding a key, so it slipped past the exact type-set pin (no digest effect: the struct is unreferenced). Under `--disable-proto=throw` it was an unsigned 500. | Fixed: `Object.fromEntries` and `Object.hasOwn` throughout the typed-data parser. |
| SG-06 | low | The approve opt-in skipped the native-value check when `amountStr` was absent, ignored `amount`, and worked without a pinned vault account. | Fixed: `amountStr` required and zero, `amount` zero when sent, opt-in refused without `vault.fireblocks_vault_account_id`. |
| SG-07 | low | A request padded with thousands of order outputs was decoded and hashed (hundreds of ms of CPU) before the single-output rule rejected it. | Fixed: typed-data arrays over 8 entries are refused while decoding. |
| SG-08 | low | Reject details and log fields echo request values with no length limit, so one request could put a megabyte into `rejectionReason` and a log line. A decision summary key named `action` or `reason` would also have overwritten the logged verdict. | Fixed: echoed strings clipped (500 characters in replies, 512 per log field); fixed log fields are written last. |
| SG-09 | low | With `config_change_action: IGNORE`, a transaction payload delivered to the config-change route came back as a signed IGNORE naming the transaction's `requestId`; the response does not bind the route. | Fixed: the config-change route rejects any payload with an `operation`. |
| SG-10 | low | Refused and unauthenticated requests each write a log line, so a flood from anyone reaching the port can rotate the decision history out of local storage. | Mitigated: docs require shipping logs off the host and exposing the port to the co-signer only. |
| SG-11 | low | The approve opt-in does not read the transaction's fee fields. | Accepted and documented: fees are bounded by the workspace's fee settings and TAP. The opt-in is off by default. |
| SG-12 | info | A uint256 string of a million digits was parsed by `BigInt` (~140 ms) before the range check refused it. | Fixed: strings over 78 digits are refused first. |
| SG-13 | info | With `signing_payload.require` off (the default), "Fireblocks signs what the guard checked" rests on Fireblocks passing the typed data through faithfully. | Accepted: the digest check runs whenever `rawTx` is present; turn `require` on once the workspace is seen to send it ([operations.md](operations.md#what-to-confirm-on-a-live-workspace)). |
| SG-14 | info | Fireblocks message fields such as a derivation path are not checked. | Accepted: every allowed message names the vault, so a signature from another key satisfies nothing. |
| SG-15 | info | `/readyz` is unauthenticated and shows the version, config hash, key fingerprints and reference price; `rejectionReason` shows the band and the reference. | Accepted: none of it is secret, and both are how operators confirm what is running. |
| SG-16 | info | Duplicate keys in the config JSON are last-wins, and the guard trusts the host clock for deadlines and staleness. | Accepted: review config changes as a diff and check the printed SHA-256; run NTP on the host. |
| SG-17 | info | `npm audit` flagged `ws` 8.18.3, pulled in through viem (GHSA-96hv-2xvq-fx4p, GHSA-58qx-3vcg-4xpx). Not reachable: the guard never opens a websocket. | Fixed: viem 2.57.4 (ws 8.21.0). The Stitch fixtures still hash to Stitch's digests. |

The runtime tree is 16 packages, all from the npm registry with integrity hashes, and `npm audit` is clean. CI checks the installed runtime tree against the lockfile on every change.
